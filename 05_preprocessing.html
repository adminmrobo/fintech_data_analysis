1환경과 자료 구조

Colab 환경과 파이썬의 자료 구조

방법: List · Tuple · Dictionary · DataFrame일상: 장보기 목록·영수증·연락처·엑셀 표

Colab은 구글의 클라우드 컴퓨터에서 파이썬을 돌려 주는 노트북이에요. 크롬으로 구글에 로그인 → Colab 검색 → 파일 → 새 노트북 → 연결 → print("hello world")면 준비 끝. 이제 데이터를 담을 "그릇"인 자료 구조를 봅니다.

이 칸에서 가져갈 한 가지

같은 고객 데이터도 List(순서 있는 목록)·Tuple(못 바꾸는 목록)·Dictionary(이름표 달린 값)·DataFrame(표)에 담을 수 있고, 분석은 대부분 DataFrame에서 한다.

왜 이 방법을 쓰나

문제 상황

데이터를 컴퓨터에 넣어야 분석할 수 있어요. 그런데 어떤 모양으로 넣어야 할까요?

앞 방법의 한계

숫자를 따로따로 변수에 넣으면 1만 명 고객을 다룰 수 없어요.

해법

여러 값을 한 그릇에 담는 자료 구조를 씁니다. 목록은 List, 이름으로 꺼내려면 Dictionary, 표 분석은 pandas DataFrame.

쉽게 말하면 장보기 목록(List), 이미 찍힌 영수증(Tuple), 전화번호부(Dictionary), 엑셀 가계부(DataFrame) — 쓰임에 따라 고르는 그릇이에요.

일상으로 치면

장보기 목록은 줄을 더하고 지울 수 있고, 영수증은 고칠 수 없고, 연락처는 이름으로 번호를 찾고, 가계부는 줄과 칸이 있는 표예요.

데이터 분석으로는

List는 순서가 있고 바꿀 수 있는 목록([ ]), Tuple은 바꿀 수 없는 목록(( )), Dictionary는 키:값 쌍({ }), Set은 중복 없는 모음이에요. 표 분석에는 numpy Array와 pandas DataFrame을 씁니다(외부 라이브러리지만 Colab에는 이미 설치돼 있어요).

2결측값·이상치

입력값 검토 — 결측값과 이상치

방법: len()·isna()·value_counts(), IQR 울타리데이터: 은행 고객 10,127명의 거래 금액

앞 칸에서 데이터를 그릇에 담았어요. 이제 담긴 값을 검토합니다. 빠진 값(결측값)은 개수를 세어 찾고, 튀는 값(이상치)은 그림으로 찾아요. 실제 거래 금액 분포에 울타리를 쳐 보세요.

이 칸에서 가져갈 한 가지

이상치는 오류일 수도, 가장 중요한 고객일 수도 있다. 울타리는 후보를 찾는 도구이고, 지울지는 이유를 확인한 뒤 정한다.

왜 이 방법을 쓰나

문제 상황

입력한 데이터에 빠진 값이나 이상한 값이 섞여 있을 수 있어요.

앞 방법의 한계

눈으로 1만 줄을 훑을 수는 없어요. 그리고 "튀는 값은 다 오류"라고 지우면 중요한 고객을 버릴 수 있어요.

해법

결측은 len()·isna()·value_counts()로 세고, 이상치는 산점도·상자그림과 IQR 울타리(Q3 + 1.5 × IQR)로 후보를 찾은 뒤, 원인을 확인합니다.

쉽게 말하면 반 키 재기에서 2m 50cm가 나오면 잘못 적은 것이지만, 농구부 2m 학생은 진짜예요. 확인 없이 지우면 안 돼요.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

IQR 울타리는 어떻게 계산해요?

학교 수학으로 보면 중학교 「자료의 정리」의 사분위수, 고등학교 「통계」의 상자그림이에요.

위쪽 울타리 = Q3 + 1.5 × IQR, IQR = Q3 − Q1
Q1작은 쪽에서 25% 지점의 값
Q3작은 쪽에서 75% 지점의 값
IQR가운데 50%가 퍼진 폭
1.5관례적인 배수. 키우면 울타리가 멀어져 이상치 후보가 줄어요
숫자로 한 번 해 보기거래 금액 Q1 = $2,156, Q3 = $4,741IQR = 4,741 − 2,156 = $2,586울타리 = 4,741 + 1.5 × 2,586 = $8,619울타리 밖 고객 = 896명

896명이나 울타리 밖이네요. 이게 다 오류일 리는 없겠죠? 거래를 많이 하는 진짜 고객들이구나.

일상으로 치면

키를 적다가 1.65를 16.5로 잘못 적으면 오류예요. 하지만 농구부 학생의 2m는 진짜 값이에요. 둘 다 "튀는 값"이지만 처리는 정반대입니다.

데이터 분석으로는

이상치는 "지울 것"이 아니라 "설명할 것"이에요. 오류(입력 실수·단위 착오)는 고치고, 진짜 극단값은 남기되 모델이 휘둘리지 않게 변환(로그)이나 강건한 지표(중앙값)를 씁니다.

이상 거래 탐지(FDS)에서는 이상치 자체가 찾는 대상이에요.

숨은 결측의 표기는 데이터마다 달라 데이터 사전을 함께 봐야 해요.

같은 방법을 보여 주는 예시 코드 — 교안 코드 아님 (몰라도 됩니다)
df.isna().sum()빈칸(NaN) 개수 — 이 데이터는 0
(df[['Education_Level','Income_Category','Marital_Status']] == 'Unknown').sum()글자로 된 숨은 결측 세기

3라벨과 세팅

라벨 붙이기와 데이터 세팅 — 모델이 먹을 수 있는 모양으로

방법: 라벨 인코딩, [1]*n, zip으로 순서쌍데이터: 은행 고객 이탈 여부

앞 칸에서 값을 검토했어요. 마지막으로 모델이 먹을 수 있는 모양을 만듭니다. 문자 정답("Attrited Customer")은 숫자(1/0)로, 입력 칸은 [거래횟수, 거래금액] 순서쌍으로 묶어요.

이 칸에서 가져갈 한 가지

분류 모델의 입력은 "특성 묶음(X)"과 "숫자 정답(y)" 두 개다. 관심 있는 쪽(이탈)을 1로 두고, 클래스 비율(불균형)을 함께 확인한다.

왜 이 방법을 쓰나

문제 상황

모델은 "Attrited Customer" 같은 글자를 계산할 수 없어요.

앞 방법의 한계

정답이 글자로 되어 있으면 모델이 학습할 수 없고, 입력이 칸마다 따로 있으면 한 고객의 특성을 함께 보지 못해요.

해법

정답을 1(이탈)·0(유지)으로 바꾸고, 고객마다 [거래횟수, 거래금액]처럼 특성을 한 쌍으로 묶어 X(입력)와 y(정답)를 만듭니다.

쉽게 말하면 시험 채점표를 만들 때 O/X를 1/0으로 바꾸고, 학생마다 국어·수학 점수를 한 줄에 적는 것과 같아요.

수식이 궁금하면 펼쳐 보기 — 수학 수식을 어려워하는 조수가 대신 물어봅니다

"모두 남는다"고만 찍어도 정확도가 84%라는 건 어떻게 계산해요?

학교 수학으로 보면 초등학교 「비율」이에요.

기준선 정확도 = 다수 클래스 수 ÷ 전체 수
다수 클래스더 많은 쪽(남은 고객 8,500명)
전체10,127명
기준선아무것도 배우지 않은 모델이 낼 수 있는 점수
숫자로 한 번 해 보기남은 고객 8,500명, 떠난 고객 1,627명8,500 ÷ 10,127 = 0.839기준선 정확도 = 83.9% → 모델은 이보다 높아야 의미가 있음

아무것도 안 배워도 84%라니, 정확도 숫자만 보면 속기 쉽겠네요. 6·7회차에서 이 숫자를 계속 확인해야겠어요.

일상으로 치면

선생님이 채점하려면 학생 이름 옆에 점수들이 한 줄로 있고, 정답 칸에 O/X가 있어야 해요. 컴퓨터는 O/X 대신 1/0을 좋아합니다.

데이터 분석으로는

교안은 생선 데이터에서 [1]*35 + [0]*14로 도미 35마리(1)와 빙어 14마리(0)의 라벨을 만들고, zip(length, weight)으로 [길이, 무게] 쌍을 만들었어요. 실제 데이터는 고객 순서가 섞여 있으니, 조건식(df.Attrition_Flag == "Attrited Customer")으로 고객마다 라벨을 붙여요.

실험 — 라벨을 붙이고 순서쌍 만들기

자세한 풀이 — 모델 입력 완성 (펼쳐 보기)
